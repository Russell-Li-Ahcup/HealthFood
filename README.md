# HealthFood 营养采购规划

根据身高、体重、年龄、活动量计算每日营养目标，自动生成一周饮食方案，并按采购日算出每次具体要买多少肉、菜、主食。

- **两种模式**：增重模式（热量盈余、高蛋白）/ 健康保持模式（维持体重、膳食均衡），每周根据体重变化建议调整热量。
- **周饮食方案**：随时整周重新随机、单餐换一个、锁定喜欢的餐；外出就餐（轻食/正常/大餐/自定义热量）会自动减少当天和之后两天其余餐的份量。
- **采购清单**：固定星期几 / 每周随机 / 手动指定日期；扣除现有库存，按购买单位（盒、个、袋）取整，提示需要冷冻的食材；上次采购没完成时会自动加一次"今天补充采购"。买多少也会对照冰箱空位：你大概估冷藏层、蔬菜盒、冰箱门、冷冻层还能放几份，清单按位置分组，挤不下时会提醒分装冷冻或下次再买。
- **保质期**：采购完成后自动入库，按保质期提醒，吃掉的餐先进先出扣减库存。
- **食材 / 菜谱库**：预置 51 种常见食材、38 道菜谱，也可以自己添加（每 100g 营养、可食部比例、单位重量、价格、保质期）。
- **数据**：存在浏览器本地（IndexedDB），可选 WebDAV / S3 多设备同步，也可以导出 / 导入 JSON 备份。

## 本地运行

需要 Node.js 20 及以上。

```bash
npm i
npm run dev
```

打开 http://localhost:3000 ，按引导填写身体数据、选择模式即可。

其他命令：

```bash
npm run build   # 生产构建
npm run start   # 启动生产版本
npm test        # 单元测试（营养计算、饮食生成、采购计算、同步合并）
npm run lint
```

## 部署到云端（Vercel）

1. 把项目推送到 GitHub。
2. 在 [Vercel](https://vercel.com/new) 导入该仓库，框架会自动识别为 Next.js，直接点 Deploy。
3. **不需要配置任何环境变量**，也不需要数据库：数据保存在每个用户自己的浏览器里。

`/api/sync/webdav` 和 `/api/sync/s3` 是同步用的代理接口（解决浏览器跨域），只转发请求，不保存任何数据。

## 多设备同步

在「设置 → 云同步」里配置，每台设备填同样的信息即可。数据保存在远端的 `/HealthFood/data.json`。

**WebDAV（以坚果云为例）**

1. 坚果云网页版 → 右上角账户 → 账户信息 → 安全选项 → 第三方应用管理 → 添加应用，生成**应用密码**。
2. 服务器地址填 `https://dav.jianguoyun.com/dav/`，账号填坚果云登录邮箱，密码填刚才的应用密码。
3. 点「测试连接」，成功后保存。

**S3 兼容存储**（AWS S3、Cloudflare R2、阿里云 OSS 等）：填 Endpoint、Region、Bucket、Access Key 和 Secret Key。

同步规则：启动时、每 10 分钟、数据修改 2 秒后、网络恢复时自动同步；两台设备都改过时按每条记录的修改时间合并（后改的生效，删除也会同步），采购清单的勾选状态会合并保留。

## 技术栈

Next.js 15（App Router）· React 19 · Tailwind CSS 4 · zustand · zod · idb-keyval · recharts · date-fns · vitest

## 目录结构

```
src/
  app/                 页面（首页、饮食计划、采购、库存、食材库、菜谱库、身体档案、设置）和同步代理 API
  components/          通用 UI、图表、餐格、模式切换
  data/presets.ts      预置食材与菜谱
  lib/nutrition/       BMI、BMR、每日目标、膳食宝塔、每周热量调整
  lib/planner/         周饮食生成、外出就餐预算
  lib/shopping/        采购日计算、采购量计算与取整
  lib/inventory/       保质期、库存扣减
  lib/sync/            WebDAV / S3 同步与合并
  lib/actions.ts       页面调用的所有数据操作
```
